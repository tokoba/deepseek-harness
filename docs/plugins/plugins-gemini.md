2026年現在、DeepSeek AIが公開したオープンソースエージェントフレームワーク **DeepSeek Harness（`dsh` / `@deepseek-ai/dsh`）** は、Cordisランタイムを基盤とした「Everything is a plugin（すべてがプラグイン）」という時空間合成性アーキテクチャを採用しており、GitHub Star数やコミュニティエコシステム（dsh-plugin.org、Redditのr/DeepSeek、r/LocalLLaMAなど）が急速に拡大しています。

現在接続されている **DeepSeek API（推論）**、**GLM（z.ai / 大規模コンテキスト・推論）**、**GitHub Copilot（モデルアクセス/コード補完）** というマルチプロバイダ構成は、トークン単価と推論能力のバランスにおいて非常に強力な基盤です。しかし、Copilot連携機能のみでは「モデルにプロンプトを投げてシェルや通常ファイルを編集させる」というエージェントの素のループにとどまり、**「設計の厳密さ」「深層コード探索」「客観的テスト・デバッグ」「セッション横断の記憶」** という実践的なエンジニアリング能力が解放されていません。

GitHub Star数、Reddit（r/LocalLLaMA, r/DeepSeekHarness）、Medium、dsh-plugin.org 等の公開情報に基づき、開発・設計・調査・テストの各フェーズで真に役立つ有力プラグインを精査・比較検討した詳細レポートをまとめました。

## 1. 領域別：実戦力を高める注目プラグイン調査

### (1) 設計・アーキテクチャ策定（Architecture & Design）

エージェントがコードを書き始める前に、前提条件の矛盾を突き、設計境界を定義するためのツール群です。

#### ① Aegis (`GanyuanRan/Aegis`)

* **概要・出自**: Jesse VincentのSuperpowersやMatt Pocockのスキル設計思想を汲み、ソフトウェアエンジニアリングの規律を埋め込む手法パッケージ（Method Pack）。
* **主な特徴**:
* **意思決定インタビュー（`Grill me` / `審問我` モード）**: エージェントが勝手な推測で実装に進むのを防ぎ、アーキテクチャの境界、契約（Contract）、前提条件について人間側に1問ずつ質問を投げかけて仕様を詰める。
* **第一原理レビュー（`aegis:first-principles-review`）**: 複雑なアーキテクチャ方針に対し、根本原理から矛盾がないかを事前検証する。
* **定量的効果**: ホールドアウトA/Bベンチマークにおいて、契約パス率が 61.67% → 93.33% に向上し、安全でない出力（破壊的変更）が 13.33% → 0% に抑制されたと報告されている。

* **適用先**: 複雑なシステム設計、モジュール間インターフェース設計、リファクタリング計画。

#### ② Archify (`archify#integrations/deepseek-harness`)

* **コミュニティ評価**: GitHub ~14.8k Stars。
* **主な特徴**:
* コードベース全体をスキャンし、MermaidやSVGベースの対話型アーキテクチャ図、コンポーネント図、データフロー図を自動生成。
* 設計レビュー時に、エージェントが提案する新設計が既存のシステムトポロジーに与える影響を視覚的かつ構造化されたドキュメントとして出力する。

* **適用先**: 既存コードのドキュメンテーション、設計ドキュメント（ADR: Architecture Decision Record）作成、新機能導入時の影響範囲可視化。

### (2) 開発・コード探索・ワークスペース（Development & Implementation）

大規模・多言語（Rust、C/C++、C#、TypeScript等）なコードベースを正確に把握し、操作摩擦を削ぎ落とすプラグイン群です。

#### ① dsh-tool-ast-grep (`jaylor-wang/dsh-tool-ast-grep`)

* **概要**: 高速な構造的コード検索ツール `ast-grep` を DSH のネイティブツールとして統合。
* **主な特徴**:
* 従来の正規表現やテキスト検索（ripgrep）では型やスコープを見落としがちだが、AST（抽象構文木）ベースでパターンマッチングを実施。
* 特定のトレイト実装、関数シグネチャ、特定のアノテーションが付与されたクラスや構造体をトークン浪費なく一撃で特定。

* **適用先**: 型安全性が重要なコードベースでの安全なリファクタリング、構文解析に基づくコード探索。

#### ② harness-github (`988hj7tczd-oss/harness-github`)

* **概要**: `gh` CLI をベースに設計された DSH ネイティブの GitHub 連携ツール。
* **主な特徴**:
* 18種類の `github_*` ツールを提供（Issueトリアージ、PR作成・レビュー、Checks確認）。
* **CIログ直結デバッグ**: `github_workflow_run` により、CI（GitHub Actions）が失敗した際に失敗ステップとキーログを即座に引き出してエージェントのコンテキストに投入可能。
* **Fail-Closed 承認ポリシー**: PRマージやコメントなどの書き込み操作はすべてユーザーの明示的承認（Human-in-the-Loop）を強制し、トークンがログに流出しない安全設計。

* **適用先**: PR駆動開発、CI/CDビルドエラーの自動分析と修正。

#### ③ DSH-better-sidebar / dsh-TUI

* **概要**: 操作インターフェースの拡張（Web派 vs ターミナル派）。
* **DSH-better-sidebar** (~2.5k Stars): DSH Web UI の右側にファイルツリー、Monacoエディタ、Git差分、本物の端末、ブラウザプレビューを配置し、VS Codeライクな作業台に変える。
* **dsh-TUI** (~2.2k Stars): Claude Code風のターミナル完結型UI。TmuxやSSH越しで素早くキーボードのみでエージェントを監督したい場合に最適。

### (3) 調査・技術リサーチ・マルチモーダル（Investigation & Research）

テキストだけでなく、長大データシート、Web画面、エラーダイアログのスクリーンショットを直接解析するプラグイン群です。

#### ① ModLens (`@liustack/modlens`) / dsh-vision-toolkit

* **コミュニティ評価**: ModLens (~3.4k Stars)、dsh-vision-toolkit (~790 Stars)。
* **主な特徴**:
* DeepSeekの標準テキストモデルや軽量推論APIに対し、視覚認識ツールを追加。
* スクリーンショットやUIモック、波形画像、GUIエラーダイアログを渡すと、構造化されたOCR、レイアウトツリー、要素関係性をJSONとしてモデルに返却する。
* `dsh-vision-toolkit` はさらにピクセル単位の差分比較やUI再構築機能を持つ。

* **適用先**: 画面UIの崩れ診断、オシロスコープ等の計測波形画像やGUIツールのエラー画面解析。

#### ② dsh-browser (`Nono-neko/dsh-browser`)

* **コミュニティ評価**: Redditやdsh-plugin.orgで上位トレンド。
* **主な特徴**:
* ホスト上の Chromium（Edge/Chrome）を `puppeteer-core` 経由で直接操作。
* 既存のログインセッションやCookieを保持したまま社内ポータル、APIドキュメント、Webコンソールを閲覧・操作可能。

* **適用先**: 最新のライブラリ公式ドキュメント調査、ローカルWebサーバーのE2E動作確認。

#### ③ Squeeze

* **概要**: 長大なPDF、技術データシート、Webページをモデルのコンテキストウィンドウを圧迫せずに読み込ませるプラグイン。
* **主な特徴**:
* 数百ページあるICデータシートや分厚い仕様書を投入した際、セマンティックチャンキングと要約を行い、エージェントが必要な章節のみをピンポイントでコンテキストに注入する。

* **適用先**: マイコン・センサー・規格票などの長大技術資料の読解・調査。

### (4) テスト・デバッグ・品質保証（Testing & Verification）

エージェント開発において最も危険な「動かないコードを『完了しました』と報告する現象（Vibes-based coding）」を撲滅するためのプラグイン群です。

#### ① dsh-plugin-debug-mode (`rh666666/dsh-plugin-debug-mode`)

* **概要**: CursorのDebug ModeをDSH向けに再現したプローブ型デバッグプラグイン。
* **主な特徴**:
* バグ調査時、エージェントが推測でコードを書き換えるのを禁止。
* 疑わしいコードパスに非侵入的な「ロギングプローブ（観測コード）」を一時挿入し、ユーザーまたはテストスクリプトに再現実行を行わせる。
* 出力された実ランタイムログを自動回収し、**事実（証拠）に基づいて真因を特定**してから修正案を作成する。

* **適用先**: 並行処理のレースコンディション、ステートマシンの不整合、ハードウェア/通信タイミング起因のバグ調査。

#### ② Aegis（TDD & Proof-before-done ルート）

* **主な特徴**:
* **厳格なTDD（`TDD Route: strict`）**: 実装前に必ず失敗するテストコードを書くことをエージェントに義務付ける。
* **証拠なき完了の拒否（`Proof before "done"`）**: テストの実行ログ、カバレッジ、境界値のパス結果という「客観的証拠」が提出されない限り、タスク完了ステータスへの遷移を認めない。
* **ゴーストコードの自動パージ**: 修正後に残った古いフォールバック処理や未使用コード（技術的負債）を検知して削除を促す。

* **適用先**: リグレッションテスト、単体テスト/結合テストの網羅性確保。

#### ③ dsh-review / dsh-review-threads

* **概要**: マルチエージェントによる並行コードレビューおよび行単位のディスカッションスレッド管理。
* **主な特徴**:
* セカンドオピニオンとして別視点（セキュリティ特化、パフォーマンス特化）のサブエージェントを走らせてコード差分をレビュー。
* DSHの差分ビュー上にGitHubのような行単位のスレッドを展開し、指摘事項を順次解消していく。

### (5) コンテキスト記憶・安全性・基盤ガバナンス（Memory & Foundation）

セッションが切れるたびに前提条件を再入力する手間をなくし、API利用料の暴走を防ぐ必須基盤です。

#### ① OpenViking (`dsh-memory-openviking`) / Hindsight

* **コミュニティ評価**: OpenViking (~38k Stars)、Hindsight (~20.7k Stars)。
* **主な特徴**:
* セッションをまたいだ**永続的記憶（Durable Memory）**。
* プロジェクト固有の設計原則、命名規則、過去に解決したバグパターンをローカルSQLiteやベクトルDBに蓄積。
* 新しいセッション開始時やステップ実行前（`agent/pre-step`）に必要なコンテキストのみを自動検索・注入する。

* **適用先**: 長期プロジェクトの文脈維持、コーディング規約の自動遵守。

#### ② dsh-budget & dsh-permission-rules

* **概要**: VPSやローカルで自律実行させる際の最重要セキュリティ・コスト防御壁。
* **主な特徴**:
* **dsh-budget**: セッション単位、日単位、月単位の消費トークン/金額にハードキャップをかけ、自律ループの暴走によるAPI残高枯渇を物理的に遮断。
* **dsh-permission-rules**: `.dsh/rules.yaml` でシェルの実行コマンド（rm, git push等）や特定ディレクトリへの書き込みにホワイトリスト/ブラックリストを適用。

#### ③ DSH ネイティブ MCP クライアント (`packages/mcp`)

* **概要**: Anthropicが提唱しデファクト化した **Model Context Protocol (MCP)** のサーバー群をDSHからシームレスに呼び出す組み込み機能。
* **主な特徴**:
* 既存の膨大なMCPエコシステム（PostgreSQL/SQLite MCP、Git MCP、Fetch MCP、ローカルファイルMCP、自作デバッグツール用Stdio MCPサーバーなど）をそのままDSHのツールとしてマウント可能。

## 3. 目的別：推奨導入ステップとロードマップ

現在の環境（DeepSeek API + GLM subscription + Copilot）を活かしつつ、開発力を最大化するための段階的導入プランです。

```
[現状]
DSH Core + (DeepSeek / GLM / Copilot)
  │
  ├─ 【Step 1: 安全ガードと作業環境の確立】
  │    ├─ dsh-budget (予算暴走防止)
  │    ├─ dsh-permission-rules (危険コマンド制限)
  │    └─ DSH-better-sidebar または dsh-TUI (作業集中環境)
  │
  ├─ 【Step 2: エンジニアリング品質・規律の強化（最重要）】
  │    ├─ Aegis (意思決定・第一原理レビュー・TDD・完了エビデンス)
  │    ├─ dsh-tool-ast-grep (ASTベースの高精度コード探索)
  │    └─ dsh-plugin-debug-mode (プローブ挿入による実証的デバッグ)
  │
  └─ 【Step 3: 調査・自動化・記憶の拡張】
       ├─ harness-github (CI失敗ログの自動回収と修正)
       ├─ OpenViking (プロジェクト文脈の永続記憶)
       ├─ ModLens (GUI・エラーダイアログのスクショ読み取り)
       └─ DSH MCP Integration (自作ツール・DBとの接続)

```

### ステップ詳細

1. **Step 1: 防壁と開発体験の整備（即時導入推奨）**

* 自律エージェントを動かす以上、まず `dsh-budget` と `dsh-permission-rules` で安全枠を確保します。
* 続いてブラウザ派なら `DSH-better-sidebar`、端末派なら `dsh-TUI` を有効化し、ツールと会話画面の往復コストをゼロにします。

1. **Step 2: ソフトウェア開発の「頭脳と検証力」を高める（コア）**

* **`Aegis` の導入**: これにより、エージェントが勝手な思い込みでコードを破壊するリスクがほぼ消滅します。特に「`Grill me`（仕様の壁打ち）」と「`Proof before done`（テスト証拠の提出）」は劇的な効果をもたらします。
* **`dsh-tool-ast-grep` と `dsh-plugin-debug-mode**`: 「正確に構造を探し、推測ではなくプローブログで原因を突き止める」という正統派のデバッグループをエージェントに実行させます。

1. **Step 3: 調査と運用の自動化**

* CIの失敗ログをGitHubから直接引いて自己修復させる `harness-github`、セッションを跨いでアーキテクチャ方針を覚えさせる `OpenViking`、エラー画面を解析する `ModLens` を投入して自律度を引き上げます。

## 4. 導入コマンドと運用の注意点

DeepSeek Harness は開発スピードが速く（Developer Preview段階）、破壊的変更が生じやすいため、以下のプラクティスが強く推奨されています。

### プラグインインストール例

Webプロファイル環境に追加する場合（`pnpm` 経由で内部解決されます）:

```bash
# プラグインマネージャー（UIから探す場合）
dsh plugin --profile web add dsh-market

# コア品質・規律パッケージ（Aegis）
dsh plugin --profile web add "github:GanyuanRan/Aegis"

# 構文探索ツール（ast-grep）
dsh plugin --profile web add @jaylor-wang/dsh-tool-ast-grep

# デバッグプローブツール
dsh plugin --profile web add @rh666666/dsh-plugin-debug-mode

# コスト上限ガード（安全対策：コミットハッシュやバージョン指定推奨）
dsh plugin --profile web add "github:PerryLink/dsh-budget#461d478"

```

*(※ CLIが `0.2.x` 系以降の場合、互換性チェックが厳格化されているため、プラグインのバージョンピン留めまたはコミットハッシュ指定での追加が最も安全です)*

### セキュリティと権限の監査チェックリスト

プラグインをインストールする際は、以下のフックポイントに注意してください:

1. **フックポイントの確認**:

* `tools/pre-execute`: すべてのツール呼び出しを監視・ブロック可能（ガード系プラグインに必須だが、悪意あるプラグインなら入力奪取の危険がある）。
* `agent/pre-step`: プロンプトや文脈を書き換え可能（メモリ系プラグインが活用）。

1. **外部ネットワーク通信の有無**:

* 単なるローカル解析ツール（ast-grepなど）であるにもかかわらず、外部の未知のURLへ `fetch` やテレメトリを送信していないかソースコードを確認する。

まずは **`Aegis`（設計・テスト規律）** と **`dsh-plugin-debug-mode`（実証デバッグ）**、そして安全運用のための **`dsh-budget`** を導入することで、手元の DeepSeek / GLM / Copilot の出力精度と堅牢性を格段に引き上げることができます。

1. プロンプトキャッシュを壊しにくい

search モードで必要なツールだけをオンデマンド注入
full モードで全ツール注入

ツール単位の選択

ツール一覧の安定化によるキャッシュヒット率の維持

これは、以前から重視されている「Cold後の再Warm化コスト」と「システムプロンプトの安定性」に直接効きます。

dsh-mcp は、OSの証明書ストアをNodeの信頼済みルートへ統合する機能を記載しており、企業CAやVPN、プロキシ環境でのHTTPS接続を考慮しています。OAuth Authorization Code + PKCE、refresh tokenによる静かな更新、環境変数注入にも対応しています。

 1. 当面、導入を後回しにしたいもの
巨大な全部入りUIバンドル：既存のカスタム改良部分と機能が重なり、原因切り分けが難しくなる。
複数の記憶基盤の同時導入：同じ事実の重複注入・矛盾・削除漏れを管理しにくい。
複数の自動レビュー／完了ゲートの重ね掛け：修正ループや停止条件が競合しやすい。
無制限の自動継続・再試行：失敗を繰り返して費用と副作用が増える。
送信先が不透明な無料モデル中継：既に3系統接続済みのあなたには、追加リスクに見合う必要性が低い。

これらは構成上の推奨です。特に第三者プラグインは、承認済みツールとは別に、あなたの権限でコードを実行できる点を重視しています。

最終提案

最初の到達点は「プラグインを多数入れた環境」ではなく、「設計判断が残り、調査に出典が付き、試験結果で完了を確認できる環境」です。

あなたの場合は、まず観測＋安全ガード＋開発手順を整え、次に検索・資料記憶を追加し、その後で接続済み3系統を少数の役割へ固定して分担させる構成が、最も評価しやすく実用的です。
