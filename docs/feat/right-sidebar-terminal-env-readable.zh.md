# 右侧栏终端环境继承

[English](right-sidebar-terminal-env-readable.md) | 中文

## 概要

本提案允许用户为右侧栏 Terminal 显式启用包含凭据的环境继承。现有过滤行为仍为默认值。Agent（智能体）shell 工具、agent 自有的持久终端、MCP 服务器、LSP 服务器和 subagent 保留各自现有的环境策略。

状态：已在当前检出中实现；未签名 Windows x64 安装程序及其内置环境策略已验证。尚未替换已安装的桌面运行时，也未复现用户报告的启动文件故障。本文记录实现设计；配置由所属的[控制器参考](../../packages/api/terminal-controller/README.zh.md)说明。

<a id="scope-and-current-evidence"></a>
## 范围与当前证据

产品行为变更仅限于从右侧栏打开、由人操作的终端。共享 subprocess 和 SSH 的变更仅用于传递并实现这一终端专用选择；不得放宽其他调用方的默认值，也不得向模型暴露新的环境覆盖参数。

| 主题 | 已检查的依据 | 含义 |
|---|---|---|
| 凭据过滤 | [共享环境辅助函数](../../packages/subprocess/subprocess/src/index.ts#L40-L79) | DSH 而非 Cordis 本身移除匹配 `KEY`、`PASSWORD`、`SECRET` 或 `TOKEN` 的名称，以及以 `DSH_` 开头的名称，均不区分大小写。 |
| 侧栏分配 | [终端控制器](../../packages/api/terminal-controller/src/index.ts#L313-L325) | 控制器显式传递 Session 身份，但不传递环境继承选择。 |
| 显式覆盖 | [本地环境合成](../../packages/subprocess/subprocess-local/src/spawn.ts#L36-L54) | 显式条目可以恢复被过滤的变量；Windows 名称按不区分大小写的规则合并。 |
| 用户权限 | [用户终端权限决策](../../.agents/notes/implemented/architecture/2026-09-16-user-terminal-permissions.zh.md) | 侧栏终端已独立于 agent 沙箱权限运行；凭据过滤是另一项策略。 |
| Shell 启动 | [侧栏 shell 配置](../../packages/api/terminal-controller/src/shells.ts#L24-L27) 与 [Bash 活动集成](../../packages/subprocess/subprocess-local/src/shell-activity.ts#L63-L96) | 侧栏默认值不禁用启动文件；受支持的 POSIX Bash 集成会显式加载用户的 `.bashrc`。 |
| Agent 终端默认值 | [Agent 终端配置](../../packages/terminal/terminal-bash/src/config.ts#L62-L67) | Agent 自有终端使用不加载配置文件的参数，不属于本提案的变更对象。 |

源码检查确认过滤机制，但不能确定每个变量缺失或启动文件故障的原因。已安装版本的差异、所选 shell、启动参数、主目录选择和父进程环境仍需运行时验证。

<a id="proposed-behavior"></a>
## 拟议行为

侧栏终端控制器公开服务器端 `environmentMode` 字段。Cordis 将此设置保存为 volatile 引用，仅改变模式的配置更新不会替换控制器或关闭已有终端。

| 值 | 拟议行为 |
|---|---|
| `scrubbed` | 默认值。保留现有凭据名称过滤及内部变量隔离。 |
| `inherit-user` | 继承执行提供方的父进程环境，不过滤凭据名称。继续隔离内部 `DSH_*` 变量，再应用终端的显式覆盖。 |

继承环境是每次分配终端时取得的快照。修改设置仅影响新终端；现有 shell 及其后代保留原环境。用户必须关闭并重新打开终端，才能改变其继承策略。

控制器根据经过验证的部署配置选择模式，而非根据浏览器输入或所选 shell 选择。无效值在配置验证阶段报错。本次变更不增加每次创建的 Remote 参数、agent 工具参数或新的侧栏控件。

`inherit-user` 会有意提供父进程中所有匹配的凭据，包括存在于其中的 DSH 模型提供方凭据，而不仅限于当前项目的凭据。保留现有的显式 `DSH_SESSION_ID` 覆盖和提供方私有控制变量处理；不得整体恢复环境中的 `DSH_*` 条目。

<a id="implementation-responsibilities"></a>
## 实现职责

环境选择属于启动进程的提供方。若控制器展开 `process.env`，复制的是 Web Host 环境；当 Session 通过 SSH 执行时，这一来源不正确。

1. 为终端启动规格增加显式的可选环境模式。省略时由提供方的环境解析步骤解析为 `scrubbed`，保留所有现有调用方的行为。不要向普通进程启动请求增加该模式。
2. 增加经过验证的控制器设置，默认值为 `scrubbed`，仅从右侧栏终端分配处传递。其他调用方保持不变。
3. 在本地 subprocess 提供方实现环境解析：选择父环境基础值，移除环境中的内部名称，应用现有代理规范化，按平台名称语义合并显式条目，并保留现有最终验证及私有控制处理。不改变 `scrubbedParentEnv()` 及其其他调用方的行为；复用现有合成职责，不另建侧栏专用合并算法。
4. 通过 SSH 终端请求、请求解析器和 helper 的终端分配传递该模式。在远端执行主机而非 SSH 客户端解析继承。同步更新所有受影响的类型调用方和线协议验证器。
5. 保留 PTY 生命周期、进程归属、尺寸、终端仿真、活动集成、输出保留和 agent 沙箱行为。凭据值不得进入设置、进程元数据、诊断信息或新增的 Session 事件。

无法遵守显式模式的提供方必须报告可操作的不支持模式错误并拒绝分配，而非静默替换环境策略。在分配前确定此类失败，避免清理尚未发布的进程。现有分配及清理失败的责任归属保持不变。

<a id="startup-files-and-windows-environment"></a>
## 启动文件与 Windows 环境

环境继承与启动文件选择是两个独立功能。本提案不取消 agent 终端的启动限制，不强制使用登录 shell，也不改写用户的启动文件。

对于侧栏 Bash，必须先验证实际可执行文件、有效参数、主目录和启动文件执行情况，再考虑增加启动绕行处理。Bash 登录配置文件与交互式非登录启动文件不可互换。在 Windows 上选择 cmd 或 PowerShell 不代表会执行 Bash 启动文件；配置的 Git Bash 或 WSL 启动器必须在其自身执行环境中调查。

对于 Windows，`inherit-user` 使用 DSH 执行进程已持有的环境。它不读取用户或系统注册表，不刷新 Explorer 环境，也不获取 DSH 启动后的变更。修改 Windows 环境设置后，应重启完整的 DSH 桌面/Host 进程，并打开新终端进行验证。仅新建终端无法更新过期的 Host 环境。

用无害的哨兵变量测试启动文件执行，并通过存在性或合成值检查凭据可用性。不要将真实环境或启动文件内容完整输出到 agent 对话中。真实用户启动配置不属于本文已检查的证据。

<a id="security-and-alternatives"></a>
## 安全与备选方案

显式启用后，shell、启动脚本、命令及后代进程均可访问继承的凭据。侧栏输出仍不自动进入 agent 历史，但终端程序、文件写入、粘贴输出、浏览器屏幕恢复或用户授权的导出仍可能泄露凭据。输出分离不保证凭据隔离。本功能不增加操作系统权限，也不豁免现有 Remote 访问检查。

该模式仅改变隐式继承。经过过滤的 shell 仍可能从可读文件、启动脚本、凭据管理器或显式覆盖中获取凭据；`scrubbed` 并不是完整的秘密隔离机制。不得声称保留过滤后，不受限的用户 shell 就无法读取秘密。

| 备选方案 | 决定 |
|---|---|
| 移除共享凭据过滤器 | 拒绝：这也会改变 agent、MCP、LSP 和 subagent 的凭据暴露范围。 |
| 增加环境变量名称允许列表 | 暂缓：暴露范围更小，但每个所需变量都需要持续维护配置；所选双模式提案不需要此项。 |
| 将 Host 的完整环境作为控制器覆盖传递 | 拒绝：SSH 下执行主机错误，并会意外恢复内部变量。 |
| 将未过滤继承设为侧栏默认值 | 暂缓：会在未显式启用时改变暴露范围；本提案保留现有安装的行为。 |

<a id="acceptance-and-verification"></a>
## 验收与验证

使用合成值、唯一临时目录和明确归属的子进程清理。下列验收条件适用于实现。平台专属用例需要在所属主机验证；源码、浏览器及打包运行时检查成功不能替代完整安装验收。

| 场景 | 必需结果 |
|---|---|
| 省略模式及显式 `scrubbed` | 合成的 `KEY`、`PASSWORD`、`SECRET` 和 `TOKEN` 变量仍不存在；普通父环境变量保留。 |
| 显式 `inherit-user` | 四类合成凭据名称均传入侧栏 shell 和子命令。 |
| 内部变量及覆盖 | 两种模式中环境的 `DSH_*` 变量均不存在；显式 Session 身份和现有私有进程控制处理保持不变。 |
| Windows 名称语义 | 混合大小写的继承名称和显式覆盖解析为单一有效变量，且不能通过大小写绕过凭据过滤。 |
| Bash 启动 | 临时可读的 `.bashrc` 在受支持的侧栏启动中导出哨兵值；此断言独立于凭据模式断言。 |
| PowerShell 启动 | 受控配置文件的哨兵值由允许加载配置文件的侧栏启动加载；agent 不加载配置文件的行为不变。 |
| 其他调用方 | Agent 普通 shell、agent 持久终端、MCP、LSP 和 subagent 的行为继续过滤，除非其原有显式覆盖提供了值。 |
| 配置及提供方失败 | 无效配置被拒绝；不支持的显式模式在分配前失败，且不泄露环境值。 |
| 生命周期 | 设置改变后，现有终端保留原环境；新终端采用新策略。 |
| SSH | 继承使用 helper 主机的合成环境，绝不使用控制器主机环境；线协议验证保留所选模式。 |
| 真实应用组合 | 使用测试覆盖启动已交付的 profile，并经 Remote 操作侧栏分配；通过无需密钥的录制场景验证两种模式及未改变的 agent 过滤。 |

聚焦测试必须覆盖控制器、本地提供方环境合成与真实 PTY 行为，以及 SSH 序列化/helper 执行。已交付 profile 测试不得用手工插件树代替真实组合。在声称已解决用户报告的问题之前，Windows 检查必须包含已安装桌面应用的执行路径。

<a id="delivery-sequence"></a>
## 交付顺序

首先复现用户已安装的侧栏 shell，并区分环境过滤与启动文件选择。随后实现显式启用策略及聚焦测试，包括保留其他调用方默认值的反向用例。不要将未经证实的启动文件修复合并到环境变更中。

字段实现后，通过正常编写或生成流程更新控制器、subprocess 文档及配置目录。审查受影响的公开类型和线协议类型，并在实现时记录实际发生的兼容性破坏。本提案不改变 Session 持久化，也不要求 Session 格式迁移。

测试现有 GUI 前，先构建受影响的桌面/Web 产物；修改当前检出不会自动更新已安装应用。仅在用户接受凭据暴露后启用此选项。回退时恢复 `scrubbed`，并关闭所有以 `inherit-user` 打开的终端；若修改过父进程配置，应另行还原。

## 开发备注

实现保留过滤默认值，不修改用户 profile，也不替换已安装应用。创建安装程序与安装验收是两个独立步骤。原始启动文件症状需要结合用户选择的 shell 和主目录验证；环境继承本身不能证明该症状已解决。
